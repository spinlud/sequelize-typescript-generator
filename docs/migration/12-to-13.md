# Migrating from 12.x to 13.0.0

Version 13 is a substantial release. The package is now ESM-only, the generator
emits Sequelize's native output by default, foreign keys become associations
automatically, and the SQLite driver has changed. This guide walks through each
breaking change in the order you are likely to hit it while upgrading, with a
concrete before/after for each, then lists what is new in 13.

## Breaking changes

### 1. ESM-only package, Node `>=22.13.0`

The package now ships as ES modules only (`"type": "module"`, a single root
`exports` entry, no dual CommonJS build). The runtime floor is raised to Node
`>=22.13.0`, which is the first version able to `require()` an ESM module that
has no top-level await. CommonJS consumers can still load the package through
`require()`, but their TypeScript must resolve modules the modern way.

CommonJS/TypeScript consumers need `module: node20` (or `nodenext`) so that
`require()` of an ESM dependency is allowed:

Before (12.x), CommonJS with legacy module resolution worked:

```jsonc
// tsconfig.json (12.x)
{
  "compilerOptions": {
    "module": "commonjs",
    "moduleResolution": "node"
  }
}
```

After (13), use a Node-aware module setting:

```jsonc
// tsconfig.json (13)
{
  "compilerOptions": {
    "module": "node20", // or "nodenext"
    "moduleResolution": "nodenext"
  }
}
```

```js
// CommonJS consumer (13) — require() of the ESM package works on Node >=22.13.0
const { SequelizeTypescriptGenerator } = require('sequelize-typescript-generator');
```

Make sure the runtime is new enough:

```bash
# Before (12.x): older Node was fine
node -v   # v14+

# After (13): Node >=22.13.0 is required
node -v   # v22.13.0 or newer
```

Deep imports into `build/` are closed by the `exports` map as a consequence of
this change; see section 6.

### 2. Native is the default output format

The generator now emits Sequelize's native output by default: plain `sequelize`
model classes with attributes typed via `InferAttributes` /
`InferCreationAttributes`, `declare`d fields, and a `static initModel` method per
model. The old `sequelize-typescript` decorator output is still available behind
the new `--format native|decorators` flag.

Native models depend on `sequelize` alone. The decorators format still requires
`sequelize-typescript` and `reflect-metadata` in the consuming project.

Before (12.x) — implicit decorators output:

```bash
stg -D sqlite -s ./db.sqlite -o ./models
```

```ts
// models/person.ts (12.x, decorators)
@Table({ tableName: "person", timestamps: false })
export class person extends Model<personAttributes, personAttributes> {
	@Column({ type: DataType.STRING })
	name!: string;
}
```

After (13) — the same command now emits native output:

```ts
// models/person.ts (13, native — default)
export class person extends Model<InferAttributes<person>, InferCreationAttributes<person>> {
	declare name: string;

	static initModel(sequelize: Sequelize): typeof person {
		person.init({
			name: { type: DataTypes.STRING, allowNull: false }
		}, { sequelize, tableName: "person", timestamps: false });
		return person;
	}
}
```

To keep the old decorator output, opt in explicitly:

```bash
stg -D sqlite -s ./db.sqlite -o ./models --format decorators
```

### 3. Associations discovered by default

Foreign keys are now turned into associations automatically. Where 12.x emitted
plain columns, 13 wires up the corresponding association mixins (and decorators,
under `--format decorators`). Pass `--no-associations` to restore the previous
behaviour of emitting foreign-key columns only.

Before (12.x) — a foreign key was just a column:

```ts
// person.ts (12.x)
export interface personAttributes {
	passport_id: number;
}
```

After (13) — the relationship is materialised:

```ts
// person.ts (13, native)
declare passport_id: number;
declare getPassport: HasOneGetAssociationMixin<passport>;
declare setPassport: HasOneSetAssociationMixin<passport, passport["passport_id"]>;
declare passport?: NonAttribute<passport>;
```

Restore the old output:

```bash
stg -D sqlite -s ./db.sqlite -o ./models --no-associations
```

### 4. SQLite driver is `@vscode/sqlite3`

The SQLite integration now uses `@vscode/sqlite3`. The old `sqlite3` package is
no longer supported.

Before (12.x):

```bash
npm install sqlite3
```

After (13):

```bash
npm uninstall sqlite3
npm install @vscode/sqlite3
```

### 5. `--lint-file` is flat-config only

When you pass `--lint-file`, the generator now expects an ESLint flat config
(`eslint.config.js`). Legacy `.eslintrc*` files fail fast instead of being read.

Before (12.x) — a legacy config was accepted:

```bash
stg -D sqlite -s ./db.sqlite -o ./models --lint-file .eslintrc.js
```

```js
// .eslintrc.js (12.x)
module.exports = {
	rules: { semi: ["error", "always"] }
};
```

After (13) — use a flat config:

```bash
stg -D sqlite -s ./db.sqlite -o ./models --lint-file eslint.config.js
```

```js
// eslint.config.js (13)
export default [
	{ rules: { semi: ["error", "always"] } }
];
```

### 6. `exports` map closes deep imports

The package `exports` map exposes only the root entry (plus `./package.json`).
Deep imports into `build/` no longer resolve. This follows from the ESM-only
change in section 1.

Before (12.x) — reaching into the build tree worked:

```ts
import { SqliteDialect } from 'sequelize-typescript-generator/build/dialects/SqliteDialect';
```

After (13) — import from the package root only:

```ts
import { SqliteDialect } from 'sequelize-typescript-generator';
```

## New in 13

These are additive and do not require changes when upgrading.

### `--paranoid`

Emit paranoid table options for tables that have a `deleted_at` / `deletedAt`
column. Requires `--timestamps`.

```bash
stg -D sqlite -s ./db.sqlite -o ./models --timestamps --paranoid
```

```ts
// table option added when a deleted_at column is present
{ sequelize, tableName: "person", timestamps: true, paranoid: true }
```

### `createDialect` factory

A `createDialect` factory is now exported from the package root, to build a
dialect instance programmatically.

```ts
import { createDialect } from 'sequelize-typescript-generator';

const dialect = createDialect('sqlite');
```

### SQL Server `schema` and `hasTrigger`

For SQL Server, the generator now sets `schema` in the emitted table options and
detects `hasTrigger` on tables that have triggers.

```ts
// table options (mssql)
{ sequelize, tableName: "person", schema: "dbo", hasTrigger: true }
```
