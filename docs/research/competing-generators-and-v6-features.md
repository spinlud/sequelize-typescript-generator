# Competing generators and unexposed Sequelize v6 model features

Research for issue [#66](https://github.com/spinlud/sequelize-typescript-generator/issues/66).
Data collected on 2026-09-08 from the npm registry (`npm view`, `npm search`), the GitHub REST API (`gh api`) and the Sequelize v6 documentation sources in `sequelize/website` (`versioned_docs/version-6.x.x`).

## 1. Tools that generate Sequelize v6 models from a live database

Method: `npm search` for "sequelize auto", "sequelize generator", "sequelize typescript models"; `gh search repos` for "sequelize typescript generator" and "sequelize-auto"; each hit checked with `npm view <pkg> version time.modified repository.url` and `gh api repos/<owner>/<repo>`. Migration generators (`sequelize-auto-migrations`, `seqmig`, `sequelize-mig`), loaders (`sequelize-auto-import`) and API generators (`graphql-sequelize-generator`) were excluded because they do not read a live schema into model files.

Takeaways for positioning:

- This is the only maintained generator whose primary output is `sequelize-typescript` decorator classes across five dialects. Its only decorator-output competitor (`sequelize-typescript-auto`) is MySQL-only and dead.
- The `sequelize-auto` lineage is the only real competitor for a *native* (`Model.init`) TypeScript output. Upstream is unmaintained since 2023; the `@snipervld` fork is the living branch and its additions (multi-schema, length validation, cross-schema FKs) show what users of native output ask for.
- Features `sequelize-auto` has that this generator does not: automatic association discovery from foreign keys, `paranoid`/`hasTrigger` detection, arbitrary `--additional` model options, `--singularize`, file-name casing, views on Postgres/MSSQL/SQLite.

## 2. Sequelize v6 model features not exposed by the current CLI

Current CLI flags (README, `Options:` block): host, port, database, schema (Postgres only), dialect, username, password, tables, skip-tables, indices, out-dir, clean, timestamps, case, storage, lint-file, ssl, protocol, associations-file, logs, dialect-options(-file), no-strict, no-views (MySQL/MariaDB only).

What the emitter already produces (`src/builders/ModelBuilder.ts`): `@Table({ tableName, schema?, timestamps, comment? })`; `@Column({ field?, primaryKey?, autoIncrement?, allowNull?, type, comment?, defaultValue? })`; `@Index` when `-i` is set; `@ForeignKey` and association decorators from the associations file. `IConfigMetadata` (`src/config/IConfig.ts`) has no field for any of the options below.

| v6 feature (source) | Current status | Cost to add | Value | Judgement |
|---|---|---|---|---|
| `paranoid` / `deletedAt` (v6 docs `core-concepts/paranoid.md`: `paranoid: true`, requires `timestamps`, custom column name via `deletedAt`) | Not emitted. `timestamps` flag exists but is a global boolean | Cheap: a `--paranoid` flag, or autodetect a `deleted_at`/`deletedAt` column the way `sequelize-auto` does (`isParanoidField`) and emit `paranoid: true, deletedAt: '<col>'` in `@Table` / `Model.init` options | High: soft-delete tables are common; without it generated models hard-delete | Add (autodetect + flag override) |
| Column `comment` (v6 docs `model-basics.md`: comments supported on MySQL, MariaDB, PostgreSQL, MSSQL) | Already emitted for columns and tables when the dialect returns it | None | Already covered | Nothing to do |
| `unique` on a column (v6 docs `validations-and-constraints.md`, "Unique Constraint") | Only expressed via `@Index({ unique })` when `-i` is passed; no `unique: true` on the column | Cheap: single-column unique indexes are already in `IIndexMetadata.unique`; emit `unique: true` on the attribute | Medium: makes `sequelize.sync()` and readers see the constraint without `-i` | Add (default on, or under the allowlist) |
| `validate` (v6 docs `validations-and-constraints.md`: per-attribute `validate: { len, is, isEmail, ... }`; `sequelize-typescript` maps `validate.len` to `@Length`) | Not emitted | Cheap for `len` from `character_maximum_length` (the `@snipervld` fork does exactly this); everything else needs user intent the DB does not carry | Medium: friendlier errors than DB overflow; low for other validators | Add `len` only, opt-in allowlist entry `validations` |
| `schema` per dialect (`@Table({ schema })`; MSSQL `dbo`, Postgres search path) | Emitted only for Postgres (`ITableMetadata.schema` commented "Postgres only"); MSSQL dialect fetches by schema but does not write it into the model | Cheap: pass the resolved schema through for MSSQL; MySQL/MariaDB/SQLite have no schema concept in Sequelize's sense | Medium: MSSQL users with non-`dbo` schemas get wrong SQL otherwise (see issue #37) | Add for MSSQL |
| Multiple schemas in one run (`@snipervld` `--schemas`) | Not supported | Moderate: table iteration is per `config.connection.schema` | Medium | Defer; note as competitor feature |
| `hasTrigger` (Sequelize `ModelOptions.hasTrigger`, used by `sequelize-auto` for MSSQL `OUTPUT` clause) | Not emitted | Cheap for MSSQL (`sys.triggers` query); no-op elsewhere | Low outside MSSQL, but a correctness bug there | Add for MSSQL only |
| `underscored` (v6 `ModelOptions.underscored`) | Not emitted; `field:` is written per column when the case transform renames it, which is the more explicit equivalent | None needed | Low | Skip; document that `--case` + `field` covers it |
| `freezeTableName` / `modelName` (v6 `model-basics.md`) | Not needed: `@Table({ tableName })` is explicit, which is what `freezeTableName` protects | None | None | Skip |
| `scopes` / `defaultScope` (v6 `other-topics/scopes.md`; `@Scopes`, `@DefaultScope` in sequelize-typescript) | Not emitted | Not derivable from the schema; would only be an empty placeholder | None | Skip |
| Hooks (v6 `other-topics/hooks.md`; `@BeforeCreate` etc.) | Not emitted | Not derivable from the schema | None | Skip |
| Virtual columns, getters/setters (v6 `core-concepts/getters-setters-virtuals.md`: `DataTypes.VIRTUAL` with `get()`/`set()`) | Not emitted | Not derivable from the schema. Generated columns (`GENERATED ALWAYS AS`) are real columns, not `VIRTUAL` | None | Skip; at most mark DB-generated columns read-only in the attributes interface |
| Model-level `indexes` in `@Table` (v6 `other-topics/indexes.md`) | Composite indexes are emitted as repeated `@Index({ name })` on each member column | None for decorator output; for native output the natural home is `options.indexes` | Medium (native format only) | Handle in the native emitter spec |

Cheap-and-valuable shortlist for the optional feature allowlist (issue #73): `paranoid` (autodetect), column `unique`, `validations` (`len` only), MSSQL `schema`, MSSQL `hasTrigger`. Everything schema-independent (scopes, hooks, virtuals, getters/setters, custom validators) is out of scope for a generator and should stay so; users add them in subclasses or via `--additional`-style pass-through options if that is ever desired.
